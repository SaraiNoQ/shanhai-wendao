# 技术架构

> 状态：已采用；M5.5 角色管理、章节地图与 PixiJS 渲染性能修复已完成，验收以 `docs/prototype-checklist.md` 为准。

## 1. 技术基线

- **构建与语言：** Vite + TypeScript，开启严格类型检查。
- **界面：** React + 原生 CSS；背包、卡牌、状态和无障碍交互使用 DOM，章节地图与卡桌的背景/角色/短特效使用按需加载的 PixiJS 8 渲染层，不把 Pixi 引入规则核心。
- **状态：** React 自带状态能力加少量纯函数，不引入全局状态库。
- **持久化：** 浏览器本地存档，支持 JSON 导出与导入；没有账号和服务器。
- **内容：** TypeScript 数据模块配合 `satisfies` 做静态校验；不建立自定义编辑器。
- **随机：** 使用 `pure-rand` 提供可种子化、可复现的纯随机序列，不调用全局 `Math.random()`。
- **校验：** 使用 Zod 校验外部导入的存档；受信任的内置内容继续使用 TypeScript 静态校验。
- **交互：** 自动优先级拖拽使用 `@dnd-kit/react`，同时保留永久可用的键盘排序按钮。
- **测试：** 使用 Vitest 测试纯逻辑和关键流程，与 Vite 复用转换和解析配置。
- **部署：** 使用 Cloudflare Vite 插件将 SPA 静态资源与 Worker API 原子部署到 `wendao.sarainoq.cn`。

选择 DOM/React 作为信息和交互层，是因为本游戏仍没有角色移动、物理碰撞或复杂场景逻辑；PixiJS 只解决用户明确要求的地图/战斗视觉层和未来图片扩展，不承担游戏规则。完整游戏引擎不会减少当前工作量。

## 2. 调研结论

- **Card Forge：** 复用规则核心与界面分离、效果/触发/目标使用统一词汇的模式；不为首批 24 张牌建立脚本语言、插件系统或 AI 模块。
- **Shattered Pixel Dungeon：** 复用随机地图必须可完成、关键探索步骤保存、内容逐步解锁的模式；不引入 LibGDX 或庞大物品继承树。
- **Antimatter Dimensions：** 复用显式离线进度、版本化存档与导入导出的模式；避免全局状态和事件中心随功能增长失控。
- **Open Poker：** 复用确定性核心、种子快照、结构化事件日志与渲染分离的模式；不引入 Three.js、GSAP 或音频引擎。
- **rot.js：** 保留为未来复杂地图候选；当前 7×7 劫境不需要寻路、FOV 或完整肉鸽工具包，因此不安装。

以上项目只提供经过验证的架构参考；不复制 GPL 项目代码。

## 3. 预期目录

应用脚手架创建后使用以下最小结构：

```text
src/
  game/       # 纯战斗、奖励、随机和离线模拟
  content/    # 卡牌、妖灵、敌人、关卡和事件数据
  state/      # 存档、迁移和玩家进度
  ui/         # React 页面与组件
  styles/     # 全局变量和页面样式
```

只有当某目录出现第二个明确职责时才继续拆分。不得创建 `services/`、`managers/`、`repositories/` 或单实现接口占位。

## 4. 核心边界

### `game`

- 输入普通可序列化数据，返回新状态和结构化事件日志。
- 不读浏览器时间、DOM、存档或随机全局变量。
- 战斗、在线自动和离线模拟复用同一个状态转换函数。
- 所有随机选择使用显式种子；所有计时使用传入的逻辑时间。

### `content`

- 只声明内容，不保存玩家状态。
- 引用稳定 ID，不直接引用 React 组件或图片对象。
- 新卡优先组合现有效果；新增 `effectId` 必须同时增加测试。

### `state`

- 负责 `saveVersion`、默认存档、读取、写入、导入、导出和迁移。
- 写入前构造完整新存档，再替换旧值，避免中途失败损坏数据。
- 时间倒退不产生额外离线收益，离线时长上限为 24 小时。

### `ui`

- 将玩家操作转成明确命令，渲染 `game` 返回的状态和事件。
- 不计算伤害、掉落、升级费用或离线收益。
- 玩家可见关键词来自统一内容定义，不在组件中复制文案。

## 5. 数据流

```text
内容数据 + 玩家存档 + 玩家命令 + 随机种子/逻辑时间
                         ↓
                    纯游戏逻辑
                         ↓
              新游戏状态 + 事件日志
                    ↙           ↘
                React UI       本地存档
```

事件日志同时驱动动画、战斗报告和调试输出，避免为三种用途重复计算。

## 6. 确定性约定

- 伤害、治疗、费用和奖励使用整数；需要比例时在最终一步向下取整。
- 同一存档 ID、关卡、战斗序号和配装派生同一随机种子。
- 洗牌、目标随机选择和掉落只能消费传入的随机源。
- 4× 速度只改变展示，不改变逻辑步长和结算结果。
- 离线模拟可以跳过动画，但不能使用另一套“战力公式”近似结果。

## 7. M1 战斗闭环范围

M1 只需要：

1. 一个可启动的 Vite 页面。
2. 一个纯战斗模块和 `pure-rand` 确定性随机源。
3. 一场主将＋两妖灵对单个敌人的占位战斗。
4. 六张起始牌、灵力、抽牌和拖拽优先级。
5. Vitest 覆盖相同种子结果一致与核心战斗分支。

不在脚手架阶段加入路由库、动画库、状态库、CSS 框架、后端 SDK 或素材生成工具。

## 8. M2 三流派与素材边界

- `BattleContent` 提供武器、功法、妖灵、卡牌和六套构筑预设；UI 切换预设时仍通过 `restart` 创建完整新战斗。
- 敌人使用数组表达，当前内容只放入一个敌人；全体效果不依赖单敌人特例。
- 符印、灼烧和破甲保存在对应单位状态；剑意、灵契、费用修正和连携冷却保存在战斗状态。
- 构筑标签直接推导三种连携，不增加解锁服务、装备占位或玩家脚本。
- 生成式 AI 只在开发期产出静态 PNG。运行时仅加载 `/public/assets/pixel`，不调用模型或外部接口。
- 卡框、文字和状态标记由 DOM/CSS 绘制；图片不包含文字。素材记录见 [素材流程](asset-pipeline.md)。

## 9. M3 收藏养成与存档边界

- 静态收藏定义保存在 `content`，玩家拥有、等级、资源、配装、词条与重铸候选保存在 `state`；存档只引用稳定 ID，不复制内容对象。
- 参考 [Antimatter Dimensions](https://github.com/IvarK/AntimatterDimensionsSourceCode) 的单一版本化玩家状态、[Shattered Pixel Dungeon](https://github.com/00-Evan/shattered-pixel-dungeon) 的内容定义与物品状态分离，以及 [Godot 官方 JSON 存档示例](https://github.com/godotengine/godot-demo-projects/blob/master/loading/serialization/save_load_json.gd) 的显式序列化边界。
- 不采用通用背包插件、对象场景序列化、云存档或额外状态库：当前固定槽位与命名收藏使用普通数据和 React 状态即可完整表达。
- `saveVersion` 当前为 4。Zod 在导入边界校验版本、类别、拥有关系、配装和主线字段；错误导入不替换当前状态，损坏的本地主存档在初始化默认进度前保留原始备份。v1/v2/v3 迁移保留已有主线并补齐 M5 字段。
- 等级与装备词条在创建战斗前派生为一份 `BattleContent` 快照；战斗运行后仍只读取显式内容与状态，保持相同存档、种子和命令序列可复现。
- 法宝主动能力与消耗品使用次数属于劫境规则，M3 只完成收藏、升级和配装槽；实际战斗按钮在 M5 接入，避免在没有劫境结算前建立临时充能状态。

## 10. M4 挂机主线与在线/离线同核

- `src/content/stages.ts` 是 30 个 `StageDefinition`、三段地域、波次、推荐标签、固定解锁、奖励和背景键的唯一内容入口；关卡使用 `EnemyId[][]` 表达 1–3 波，不把缩放后的运行时属性写回内容。
- `src/game/campaign.ts` 负责 `StageSession`、`createStageSession`、`advanceStageSession`、`simulateCampaign`、`summarizeBattle` 和阶段结算。它显式接收存档、内容、经过的逻辑时间和随机种子，不读 DOM、系统时间或全局随机源。
- 在线自动、手动接管和离线批量模拟都通过 `transitionBattle` 推进同一 `BattleState`；固定逻辑步为 250ms，单波超过 180 秒判定输出不足，离线输入最多取 24 小时。离线只跳过渲染和逐条事件保留，不另写“战力公式”。
- `settleStage` 只按唯一 `sourceId` 发放首次/重复奖励；`pendingOfflineSettlement` 先保存报告，`claimOfflineSettlement` 校验 `reportId` 后一次性领取，重复领取返回原存档。
- 失败时停止撞击失败关并刷 `stableStage`；稳定关也失败则逐关回退，第一关失败时暂停。第 30 关胜利只设置 `trialUnlocked` 并暂停，不自动完成筑基。

### 10.1 M4 存档迁移与时间边界

- `PlayerSave.saveVersion` 为 `4`，`campaign` 另外可选保存最近一次 `lastFailure`（失败关、回退关、原因和战斗序号），让稳定刷取不会把卡关提醒冲掉。
- `v1/v2/v3 → v4` 迁移保留资源、收藏、等级、配装和词条；v1 初始化 M4 主线，v2/v3 保留已有主线进度并补齐劫境字段；迁移失败、结构损坏或导入校验失败不得覆盖当前有效存档。
- `lastActiveAtMs` 只在载入、阶段结算、`visibilitychange` 和 `pagehide` 更新。时间倒退按 0 处理，离线时间按 24 小时封顶，不依赖浏览器后台定时器。
- 24 小时固定步模拟在开发机测得约 4 秒，已达到可感知卡顿阈值；生产端通过 Vite 原生模块 Web Worker 调用同一个 `simulateCampaign`，主线程只接收待领取结算。Worker 不含第二套规则，也不新增依赖。

### 10.2 M4.5 反馈与可读性边界

- 自动优先级通过 `getCardAvailability` 统一判断费用和目标；自动模式跳过无合法目标的牌，不能因死亡妖灵或非法指定目标软锁。
- 手动接管保留结束态，结果层必须提供“返回游历并结算”和“重试本关”；在线自动结束仍即时结算。
- `lastFailure` 作为持久卡关提醒，游历页用 `role="alert"` 展示失败关、原因和回退关，并提供调整构筑与重新挑战入口。
- 游历和斗法正文最低 12px、辅助文字最低 10px；暗色古卷保留，但纹理遮罩不得牺牲普通文字 4.5:1 对比度。60 秒和 150 秒显示久战预警，180 秒由既有规则判败。
- 第 4、6 关保留两波结构但第二波各减少一名随从，用于平滑新存档前期节奏；其余关卡公式不变。

## 11. M5 劫境与实例化牌组

- `src/game/trial.ts` 是劫境唯一纯逻辑入口：地图生成、迷雾、行炁、劫印、格子 pending、事件选择、临时牌组、三种结算均返回可序列化状态和事件。
- 地图直接保存到 `TrialRun.grid`，恢复时不重新生成；战斗中间状态不入存档，刷新后以种子、战斗序号和格子 ID 重开当前遭遇。
- `BattleCardInstance` 让同名牌可以独立升级或耗用；主线无 setup 时继续使用旧 `CardId` 路径，保持 M1–M4.5 兼容。
- 装备、词条、法宝和消耗品通过 `BattleContent.modifiers`、充能和次数进入同一 `transitionBattle`，不增加物品脚本语言。
- `saveVersion` 当前为 4；v1/v2/v3 迁移补齐 `realmId`、劫境运行、结算幂等 ID 和志怪录字段，错误导入不会覆盖当前存档。

## 11.1 M5 图鉴与素材边界

- 志怪录独立于养成收藏，收录 14 个敌人与 8 个事件；发现状态保存稳定 ID，不参与升级或掉落。
- 首批 13 件 M5 素材只服务劫境背景和核心收藏图鉴；其余卡牌、装备、敌人与事件继续使用 CSS/墨影占位。
- 图片仍是开发期静态 PNG，运行时不调用 AI、联网服务或素材后台；完整提示词和后处理记录见 [素材流程](asset-pipeline.md)。

## 12. M4 主线美术边界

- 开发期使用 Codex 内置 GPT Image 生成 17 件主线样板：2 张地域背景、5 只妖灵、1 个首领、3 个普通敌人、3 个精英和 3 张招牌卡图。完整提示词、参考图、元数据、异常和路径以 [素材流程](asset-pipeline.md) 为唯一来源。
- 背景为 960×540，角色/敌人为 256×256 透明 PNG，卡图为 320×180；背景与卡图采用 FFmpeg 最近邻缩放和约 32 色量化，透明角色保留 alpha。
- 图片不得包含文字、数字、卡框、Logo 或水印；名称、数值、描述和状态继续由 DOM/CSS 绘制。没有正式素材的内容使用统一墨影或占位图，不阻塞主线逻辑。
- AI 只在开发期生成静态文件，运行时不调用模型、联网服务或素材管理后台。千年槐姥素材用于图鉴、劫境预告和三阶段首领战。

## 13. M5.5 页面、渲染与性能边界

- 角色管理页复用 `PlayerSave.loadout`，拖拽、点击和键盘操作统一经过 `src/state/loadout.ts`；战斗/劫境期间禁止改变正在运行的配装。
- `src/content/details.ts` 与 `src/content/effects.ts` 是详情数值和收藏效果的共享来源；角色页负责操作，图鉴负责只读展示。
- `ChapterMapScene` 只渲染当前章节；PixiJS 负责章节/战斗背景、路线、单位和短特效，DOM 负责节点按钮、数值、手牌、日志、目标选择和无障碍。
- Pixi 初始化失败时使用同一数据的 DOM/SVG/CSS 回退；减弱动态或页面隐藏时停止 ticker，不影响战斗规则推进。
- `GAME_ASSETS` 记录图片尺寸、文件和场景 Bundle；Vite 指纹代码输出到 `/assets/build`，稳定像素素材保留在 `/assets/pixel`。
- `public/_headers` 对指纹代码启用一年 `immutable`，对稳定像素素材启用一天缓存和 stale-while-revalidate；HTML 保持重新验证。
- 离线 Worker 只依赖纯玩家规则，不加载 Zod；不使用 Service Worker、PWA、WASM 或通用游戏引擎。只有短基准证明规则计算仍是瓶颈时才重新评估。

## 14. Cloudflare 部署边界

- Worker 是 `wendao.sarainoq.cn` 的源站，Custom Domain 负责 DNS 与证书；不发布 `workers.dev` 或 Preview URL。
- Vite 构建同时生成前端资源和 Worker 部署配置，Wrangler 一次上传，避免前后端版本漂移。
- 静态资源优先直接响应，只有 `/api/*` 先执行 `worker/index.ts`；SPA 未命中路径回退到 `index.html`。
- 第一版后端只有无状态 `/api/health`。本地游戏状态继续留在浏览器，不接入 D1、KV 或账号系统。
- Worker 使用标准 Fetch API，不启用 `nodejs_compat`，保持运行时依赖最小。
